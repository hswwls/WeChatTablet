# QQ 设备风险：检测点清单与实机取证记录

> 分析对象：QQ `9.3.70`（`versionCode 16410`，NT 架构）
> 分析方式：APK 静态扫描（41 个 dex + 全部 arm64 原生库）+ LSPosed 运行期 hook 观测
> 说明：文中所有设备指纹、QQ 号、报文原文均已脱敏

---

## 1. 结论先行

QQ 客户端把环境检测结果通过 SSO 上报腾讯风控服务端，服务端据此把**设备**标记为风险设备并下线。
实测抓到的完整链路：

```
[检测] libfekit.so / libnative-memory-library-lib.so / libturingxq.so / Java 层探测
   ↓
[汇聚] com.tencent.mobileqq.fe.FEKit  ──(JNI)──► com.tencent.mobileqq.qsec.qsecurity.QSec
   ↓
[上报] QSec.reportLog / doReport  →  MsfCore.sendSsoMsg(ToServiceMsg)
   ↓
[通道] trpc.o3.report.Report.SsoReport
       trpc.gc_indust.device_report.SsoHome.SsoHomeReport
       CliLogSvc.UploadReq
       trpc.qqlog.qqlog_server.Portal.SsoGetQimeiCheckReport（登录失败按 Qimei 上报）
   ↓
[服务端] 设备风险标记 → QQ 安全中心"已登录设备风险提醒"→ 平台对风险设备下线
```

## 3. Java 层检测点（真机运行时实测）

| 检测点 | 实现位置 | 实测现象 |
|---|---|---|
| root 探针 | `Runtime.exec` / `ProcessBuilder` | `/system/bin/sh -c type su`，单次运行 40+ 次（分钟级轮询） |
| su 路径表 | `File.exists/canRead/canExecute` | 字符串表含 `/system/bin/su`、`/system/xbin/su`、`/sbin/su`、`/su/bin`、`/data/local/{su,bin/su,xbin/su}`、`Superuser` |
| 模拟器属性 | `SystemProperties.get` | `init.svc.qemud`、`init.svc.droid4x`、`init.svc.noxd`、`init.svc.ttVM_x86-setup`、`init.svc.vbox86-setup`、`init.svc.qemu-props`、`init.svc.su_kpbs_daemon`、`microvirt.vbox_dpi`、goldfish/`/dev/socket/qemud`/`genyd` |
| 调试检测 | `Debug.isDebuggerConnected()`、`/proc/self/status`、`ro.debuggable`、`ro.secure` | 实测 `isDebuggerConnected()` 返回 false |
| 包枚举 | `PackageManager.getPackageInfo` | 实测查询 `de.robv.android.xposed.installer`、`com.topjohnwu.magisk`（**黑名单来自 native 与云端下发，dex 内 0 命中**） |
| maps 文本读取 | `BufferedReader` 读 `/proc/self/maps` | 实测读到模块自身 APK 的映射行 |
| hook 检查 | dex 内存在 `checkHook hookRet:%b` 字符串 | 未在运行期触发（`QSec.detectMethod` 也从未被调用） |
| 无障碍/输入法 | `Settings.Secure.getString` | 实测读取 `enabled_accessibility_services`、`default_input_method` |
| 进程枚举 | `ActivityManager.getRunning*` | 实测 `getRunningAppProcesses()` 只能看到自身 1–2 条 |
| 网络/代理 | `getNetworkCapabilities`、`http.proxyHost` | 存在调用（属性读取） |
| 安全模式 | `FEKit.checkSafeMode/initSafeMode/checkResetSafeMode/checkStatus` | `checkStatus()` 实测返回 true（SDK 正常起跑） |


## 6. 踩过的坑（重要）

| 坑 | 现象 | 处理 |
|---|---|---|
| 拦截 `wtlogin.device_lock` | 登录方拿不到设备锁校验结果 → 报"安全提醒：身份验证失败，请你重新登录。(w21)" | 加入 `KEEP_COMMANDS` 白名单，绝对放行 |
| hook `Class.forName` | QQ 启动 `SingletonPool` 建 `ISettingApi` 抛 `ClassNotFoundException` → `FATAL EXCEPTION`（类加载路径内做日志/加载类会递归自锁） | 移除该类钩子，代码内注释禁止再挂 |
| 只换 Java 侧指纹 | 报文里"新 Qimei + native attestation（旧设备）"可能跨源不一致 | 需 native 层配合（见 README 第八节） |
| 依赖 LSPosed 日志留存 | 日志只保留当前/上一次会话，设备重启 + USB 掉线会丢失关键窗口 | PC 侧做持久化抓取（自动重连 + 跟随轮转） |
